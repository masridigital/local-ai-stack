# Deploy checklist

Do not put PHI on this stack until Marko has cleared the build and every line below is true. The Anthropic switch ships **off**.

1. VM is Ubuntu Server LTS, LUKS is up, `/var/lib/local-ai-stack` is on that volume.
2. `deploy/install.sh --apply` has been run (or `ansible-playbook -i ansible/inventory.ini ansible/site.yml`). `cloudflared` is disabled. `ss` shows no public listen except SSH from the VPN, and Caddy only on `127.0.0.1` or `VPN_BIND_IP`. Presidio, the gateway, and Postgres are on `127.0.0.1`. LiteLLM is on `127.0.0.2:4000`. `scripts/check_luks.py --target /var/lib/local-ai-stack` succeeded.
3. UFW default deny incoming and outgoing. Owner rules match `deploy/ufw/owner.rules`. The Open WebUI REJECT is ahead of the loopback accept. `egress-proxy.service` listens on `127.0.0.1:8888` (Open WebUI, Entra only) and `127.0.0.1:8889` (LiteLLM). nftables rejects every other uid on those ports before the loopback accept. `api.anthropic.com` is absent unless `ANTHROPIC_BAA_ENABLED=true`. `AZURE_API_HOST` is one label whose name includes a US region from `litellm/policy.yaml` and ends in `.openai.azure.com`. Confirm with the checks in `docs/egress-proxy.md`.
4. Credential files exist, mode 0600, root-owned, under `/etc/litellm`, `/etc/policy-gateway`, `/etc/open-webui`, and `/etc/postgres`: Postgres password, database URL, audit URL, LiteLLM master key, scoped LiteLLM virtual key (gateway only), Azure client secret, Open WebUI secret, bootstrap admin password, Entra client secret, and the gateway client key (Open WebUI and the gateway). The Anthropic key exists only when `ANTHROPIC_BAA_ENABLED=true`. `install.sh` does not write `/etc/cloudflared/credentials.json`. `MICROSOFT_CLIENT_ID` is not the zero GUID.
5. **ZDR.** `anthropic_zdr_confirmed_by_cap` is true. Cap attested in chat on 2026-10-15 ("BAA has ZDR"). Formal document verification is still pending at Cap's 8 AM review. Before `ANTHROPIC_BAA_ENABLED=true`, confirm in the Anthropic console that this exact API key and organization are the HIPAA org covered by the BAA and that zero data retention is on for that org. Record the date and the org id in the evidence pack. A key from another org stays blocked.
6. Foundry deployment name is set in `AZURE_OPENAI_DEPLOYMENT`. The deployment is Azure OpenAI, Microsoft-hosted, family `gpt-4.1` or `gpt-4o` (including the mini/nano ids in the policy). It is not an `azure_ai/` marketplace model.
7. Abuse-monitoring / human-review opt-out is unchanged unless Cap already has written approval. Do not flip `FOUNDRY_ABUSE_MONITORING_OPT_OUT` on a guess.
8. Entra app uses PKCE (`S256`). Open WebUI’s tenant variable is `MICROSOFT_CLIENT_TENANT_ID` (`f7812296-5bce-41dc-8102-b1b270e7c4c7`), not `AZURE_TENANT_ID` (that name is LiteLLM Foundry only; set it to the same tenant). Redirect `https://webui.lan.internal/oauth/microsoft/callback`. Enterprise app **Assignment required = Yes**, scoped only to the `PHI-users` group. App roles are `phi`, `non-phi`, and `admin`. Local signup is off. OAuth signup remains only for people already in that group. The password form is off. The admin is the bootstrap account, not the first Entra sign-in. Conditional Access requires MFA. Admin sign-in is phishing-resistant, with an 8-hour sign-in frequency.
9. A synthetic prompt (the fixture MRN, not real PHI) is masked in the audit row and the row has no raw identifier.
10. Backup restore has a scheduled owner and a quarterly date. Break-glass secret is in the vault, not on the disk in cleartext beyond the sealed file used during an incident.
